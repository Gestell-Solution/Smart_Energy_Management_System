{\bfseries{Root Cause Analysis\+:}}

Both ISR vectors call the {\bfseries{exact same global callback pointer}}. Since OCR1A and OCR1B are both set to 1250 (same as TOP), both interrupts fire at the exact same instant every timer cycle.

{\bfseries{Detailed Timeline\+:}}

CPU Clock\+: 8 MHz Prescaler\+: 64 Timer Clock\+: 8MHz / 64 = 125 k\+Hz Timer Period\+: 1 / 125k\+Hz = 8μs per tick

Target Period\+: 1250 ticks × 8μs = 10ms = 100 Hz

Actual Behavior\+: t = 0ms\+: Counter = 0 t = 10ms\+: Counter = 1250 → OCR1A match →\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}\+\_\+\+\_\+vector\+\_\+7()\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*} → Callback() \mbox{[}Call \#1\mbox{]} → OCR1B match →\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}\+\_\+\+\_\+vector\+\_\+8()\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*} → Callback() \mbox{[}Call \#2\mbox{]} → Counter resets to 0 (CTC mode) t = 20ms\+: Repeat...

Result\+: Callback invoked TWICE per 10ms period!\hypertarget{md_Doc_2Embedded_2Analysis_2Code__Analysis__ReportV2_autotoc_md3227}{}\doxyparagraph{\texorpdfstring{💥 System Impact Analysis}{💥 System Impact Analysis}}\label{md_Doc_2Embedded_2Analysis_2Code__Analysis__ReportV2_autotoc_md3227}

{\bfseries{Problem Analysis\+:}}

The {\ttfamily EEWE} (EEPROM Write Enable) bit is automatically cleared by hardware when write completes. Normally takes 3.\+3ms. But if\+:


\begin{DoxyItemize}
\item EEPROM hardware fails
\item Power brownout during write
\item Clock issue
\item Cosmic ray bit flip (rare but possible)
\end{DoxyItemize}

Then {\ttfamily EEWE} might never clear → {\bfseries{infinite loop}} → system hangs forever!
